# No-login private Android trial

The release entrypoint opens an isolated normal-user workspace automatically. A cryptographically random 256-bit device bearer secret is saved to Android secure storage before the first network request. Only its SHA-256 digest is stored server-side. Retrying after a lost response or restarting the server resolves the same user. Tokens retain the existing owner-only product/content/media rules; no shared account or embedded provider key is used.

This is a bounded private trial, not unrestricted public registration: ten device identities total, eight AI attempts/user/day (existing default), and fifty AI attempts globally/day, including failed requests. The global quota also applies to existing normal users. Reservations are transactional. A stranger can consume unused enrollment slots; do not distribute publicly without stronger admission controls and storage quotas. Clearing app data/reinstalling may lose the device secret and therefore access; do not treat this as account recovery. There is no cross-device synchronization of identity.

Deployment requires explicit owner approval because it changes the production schema, enables a public device bootstrap route, and restarts PocketBase. Stage reviewed files under `/home/chatgpt-admin/scc-production-prep`, then run the reviewed `deploy_guest_trial.sh` from the authorized root console. It takes a consistent local backup while PocketBase is stopped, applies only the guest migration, installs the guest and AI hooks, enables `SCC_GUEST_ENABLED=1` in the existing root-only environment file, and verifies health and route guards. Existing WAHA, Caddy, Shopify and host port bindings are unchanged. Failure restores hooks/environment and restarts the previous service; the additive guest schema is retained, not destructively rolled back. The backup is local, not disaster recovery.

To stop new/renewed guest sessions set `SCC_GUEST_ENABLED=0` and recreate PocketBase. Existing user tokens remain valid until expiry; to revoke one device, mark its private device row disabled and rotate that user's token key. Do not delete device mappings to reset quotas casually.

Validation: `python3 test_guest_access.py /path/to/pocketbase` runs against disposable PocketBase 0.40.6 storage and an intentionally unavailable local upstream, never production or a billable provider. It covers bootstrap, malformed input, repeated/concurrent requests, restart recovery, product/content owner isolation, locked generic signup/private registry, provider failure, user/global quota and the device cap. Flutter tests cover persistent identity after network failure and the no-login startup UI. Real Android/provider end-to-end validation is still required after deployment. Google configuration is not required for this trial.
